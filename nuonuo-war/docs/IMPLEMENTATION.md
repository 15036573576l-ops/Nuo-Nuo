# 糯糯战记 · 实现说明（平原版）

单机网页战斗游戏，玩家对电脑，不联网。纯原生 JS，没有框架，没有 npm 依赖。战场是一张 8000 × 3200 像素的平原，兵有上下左右的位置，朝敌方水晶推进，遇到敌人就打。

契约见 `docs/PLANE_SPEC.md`；规则上的取舍见 `docs/QUESTIONS.md`；远端的 review 见 `docs/REVIEW.md`。

## 构建和测试

```
python3 tools/build_game.py      # 生成 dist/game.html，双击即可打开
node tools/headless_test.js      # 无头测试：机制断言、技能场景、撒旦、规模压力、AI 对 AI
GAMES=40 node tools/headless_test.js   # AI 对 AI 局数可调（默认 20）
```

`dist/gallery.html` 是英雄图鉴，仍由 `tools/build_gallery.py` 构建，本轮没有改动。

逻辑和渲染分开：`combat.js`、`engine.js`、`ai.js`、`special.js` 不碰 DOM 和 canvas，测试在 node 的 vm 里直接加载它们。

## 主循环

`engine.update(realDt)` 把真实时间换成固定步长：`Engine.DT = 1/30` 秒，每帧最多 12 步。`speed` 为 1 或 2（作弊菜单里还能设 0.5× 到 8×）。

一步 `step(dt)` 的顺序：

1. AI 的 `tick`（可能调用 `spawn`）
2. 经济：金币 +（基础收入 × 难度系数 + 贪婪宝箱 × 3）× dt；出兵冷却递减；手动技能冷却递减
3. 每个单位：状态计时和持续伤害、骨堆计时、技能冷却、盾墙计时、召唤物寿命、撒旦的光环
4. 重建空间网格
5. 每个单位 `updateUnit`：冲锋 → 蓄力 → 控制（眩晕、冻结）→ 技能 → 挥击或找目标 → 移动
6. 分离推挤，然后重建网格
7. 投射物落地（在回调里结算伤害）
8. 区域（火雨）、特效、尸体计时
9. 水晶炮塔
10. 结算死亡：骨堆、尸体、召唤物消散、死亡特性、撒旦复活
11. 胜负判定：一方水晶归零就结束；双方在同一步归零记为平局

死亡是延后结算的：伤害函数只把 `hp ≤ 0` 的单位放进 `pending`，在步末统一处理，同一步里别的单位不会因为别人的死亡而改变行为。

## 空间和移动

- **空间网格**：`Engine.Grid`，cell 96 像素，每步重建两次（开始时和推挤之后）。索敌、仇恨、溅射、区域、推挤都用它查询，不做全表扫描。
- **攻击距离**：中心到中心的距离 ≤ `range + radius + 目标 radius + 4`。远程（射程 ≥ 100）可以打飞行单位，`groundOnly` 的除外。
- **仇恨（追击）**：每 0.25 秒找一次，范围 `max(320, range + 200)`，取最近的可攻击敌人。蝙蝠的追击目标是全图最近的远程敌人。
- **移动**：有追击目标且不在攻击距离内就朝它走；否则朝敌方水晶走。攻击距离内有目标就停下挥击，挥击期间不移动。蠕虫移动时钻地（不能被打，速度 ×1.5）。巨像只朝水晶走，不找单位。
- **推挤**：地面单位（不含飞行、巨像、钻地、骨堆）两两中心距离小于半径之和就互相推开，各移动一半的重叠量。水晶是静态圆，地面单位被推出水晶圆外。所有单位限制在地图范围内。
- **半径**：`max(12, min(40, bodyW × 0.45))`，巨像至少 30。

## 攻击和投射物

- 攻击周期 `1 / (aspd × 减速系数)`，伤害在 release 帧结算，不是攻击开始时。release 时目标已经不在距离内就重新找，找不到就空挥。
- 远程单位发射投射物：飞行时间 `距离 / 900`（0.12–0.7 秒），高度是抛物线。追踪目标的投射物每帧取目标当前位置；炸弹落在发射时的位置，目标死了也会溅射。没有专用图的法术用元素颜色的光球。
- 溅射是圆形范围内的敌方全部受伤；骨堆被溅射会散架。

## 伤害管线

`Combat.damage(eng, src, tgt, base, dmgType, o)` 的顺序：

1. 水晶：按重甲算，攻城 ×3。水晶也吃攻击方的衰弱、雷克斯光环、易伤、作弊的伤害倍率。
2. 骨堆：只吃圣属性和溅射，直接散架。
3. 无敌（不屈的 1.5 秒、不灭的 3 秒、作弊的单位无敌）：不受伤。
4. 闪避（札斯 30% 闪避穿刺）和格挡（玄每第 4 次攻击完全格挡）。
5. 倍率：伤害类型 × 护甲（`RULES.damageMatrix`），然后攻击方的衰弱、雷克斯光环、希尔薇对飞行 ×1.5、芙蕾雅对飞行或冲锋中 ×2、圣属性对不死 ×1.5、札斯的第一刀 ×2；被打方的史莱姆修正、易伤 ×1.2、盾墙（穿刺）×0.3、撒旦和作弊的伤害倍率。
6. 圣盾吸收，然后扣血，不屈判定，致死则登记死亡。
7. 元素反应：燃烧或冰冻的目标被火打 → 融化；中毒 3 层以上被火打 → 爆燃。

飘字颜色：倍率 > 1 时黄色，否则白色。

## 状态和特殊单位

- **状态**：`Combat.applyStatus` 统一入口，叠层、时长、系数都从 `RULES.statuses` 读。寒霜叠满 3 层转冻结，冻结后 4 秒免疫；眩晕后 2 秒免疫；巨型眩晕减半；不死免疫中毒；雷克斯光环内的单位免疫衰弱。
- **撒旦**（只有玩家能出，出兵栏最后一格，X 键）：2 万血、重甲、魔法溅射，免疫控制和诅咒。炼狱光环每 0.5 秒对 200 范围内的敌人造成 30 火伤。第一次死亡原地复活，回满血，无敌 3 秒。三个手动技能：J 地狱火雨（全场 400 火伤 + 3 层灼烧，敌方水晶 500 伤害），K 深渊威压（全场击退 180 + 眩晕 4 秒），L 灵魂收割（处决全场生命 < 40% 的敌军，每个 +25 金币，最多 8 个变成骷髅）。冷却在 `sides[s].manualCd`。
- **作弊菜单**（C 键或右上角“作弊”）：加钱、收入倍率、无冷却、无限人口、水晶血量和上限（最高 1 亿）、水晶无敌、伤害倍率、单位无敌、电脑停止出兵、电脑收入倍率、速度、秒杀。设置跨局保留，每局复制进新引擎；默认全关。

## 电脑 AI

`AI.attach(eng, side, level)` 注册到引擎，每隔一段时间做一次决策，只调用 `eng.canSpawn` 和 `eng.spawn`。

| 难度 | 收入 | 决策间隔 | 策略 |
|---|---|---|---|
| 简单 | ×0.8 | 1.6–3.0 秒 | 随机买一个买得起的兵，40% 的时候不买 |
| 普通 | ×1.0 | 0.5–0.9 秒 | 打分选兵 |
| 困难 | ×1.15 | 0.35–0.6 秒 | 同普通，另外会抢贪婪宝箱发育 |

打分：克制匹配（+1 / -0.8 每种对方兵，最多按 3 个计）、飞行（远程对飞行加分）、阵型、时间峰值、花费（前两分钟按性价比）、刷屏（同兵种场上越多越不想买）、随机。这一轮的修改：

- 同兵种降权按累计出兵次数（`sides[s].spawned`）算，不再按场上在场个数。
- 每个兵种按人口的价值算，灰鼠群不再因为便宜就一直高分。
- 节奏规则：开局 2 分钟后，场上没有 T0.5 和 T0 的兵，就从这两档里挑一个，攒够钱就出，并且已经出过的少想一点。这样雷克斯能出场。

20 局里灰鼠群占双方出兵的 24.1%（上限 25%），雷克斯出场 17 局。

## 画面和界面

- **投影**：斜视 3/4 视角。`sx = (x - cam.x) × zoom + 视口宽 / 2`，`sy = (y - cam.y) × zoom × 0.6 + 视口高 / 2`。单位是侧面精灵，脚底锚点画在 (sx, sy)；地面圆画成椭圆。单位按 y 排序绘制。
- **地面烘焙**：草地、草丛、土路、树丛、石头、花，烘焙成一张半分辨率的离屏画布。烘焙是分块的（每帧 8 毫秒预算），不会卡住启动。绘制时只取视野对应的源矩形。
- **LOD**：`zoom < 0.5` 或超出 900 个预算的单位画成阵营色圆点；视野外的单位不画。
- **相机**：`zoom ∈ [0.22, 1.8]`，初始 0.7。鼠标拖动、滚轮缩放（以指针为中心）、方向键和 WASD 平移、`[` `]` 缩放、小地图点击或拖动、触屏单指拖动和双指缩放、“跟随战斗”开关和 +/− 按钮。跟随目标是挥击单位的加权平均（再平滑），手动操作后 3 秒暂停跟随。
- **HUD**：双方水晶血条、金币（+收入）、人口、时间、速度、暂停、在场单位数（我方 / 电脑）。小地图画整张地图和视野框。
- **快捷键**：Q–P 出兵，X 撒旦，J / K / L 撒旦技能，C 作弊菜单，Space 暂停，Z 倍速，WASD / 方向键平移，`[` `]` 缩放。Ctrl、Meta、Alt 组合键留给浏览器。
- **简介浮窗**：鼠标悬停或触屏长按（420 毫秒）弹出，包含伤害类型、护甲、元素、射程、移速、生命、特性、技能、克制和怕的兵种、设定文字。
- **结束**：水晶被打爆后等 1.6 秒，显示胜负、用时和双方出兵统计；“再来一局”沿用同一个难度。

## 测试结果

在我这边单独跑的结果（`node tools/headless_test.js`，约 3 分钟）：

- 机制断言：全部通过（包括 2D 分离推挤、巨像穿过单位、飞行越过地面单位、单位不越界、水晶吃易伤、撒旦复活、作弊默认关闭等）。
- 主动技能定点场景 12 项：全部通过。撒旦三个手动技能：全部通过。
- 规模压力（只统计逻辑，不渲染）：200 对 200 为 3.3 ms 每步（上限 10 ms），500 对 500 为 8.1 ms 每步（上限 25 ms）。
- AI 对 AI 20 局：**分出胜负 9 局，超时 11 局**（900 秒游戏时间仍未分胜负），平局 0 局，NaN 0 次。这一项没有通过，见下面的“已知问题”。
- 在场单位：单局峰值平均 67（双方合计），最高 83。这离“庞大军团”的目标（单方 100–300）还有很大差距。

浏览器测试（Chromium 无头模式，之前一轮）：控制台无报错，开局、出兵、作弊菜单、撒旦召唤、结束和再来一局的流程正常。

## 已知问题

- **前线僵持，超时 11 / 20 局。** 不是死锁：我单步追踪过，超时的那局里单位都在正常挥击、移动或复活，水晶血量全程 6000 不变。原因是两军在中间互相消耗，补充的兵从出生点走 2000 像素才到前线，前线的位置长期不动（兰彻斯特式僵持）。单位“遇到敌人就停下挥击”，所以推进是靠消耗，而两个对称的 AI 消耗速度差不多，就会一直拖下去。这和地图变大直接相关：旧的兵线只有 1600 像素，同样的规则下对局只要 3–4 分钟。
- **军团规模偏小。** 在场单位峰值平均 67（双方合计），而目标是单方 100–300。原因是 AI 花光金币后补兵很慢，兵又在前线陆续阵亡。引擎本身能跑 1000 单位（规模压力测试），是对局里的经济和战斗节奏限制了规模，不是性能。
- 前线僵持的解决方案需要设计决定，见本轮的交接说明：可以让兵边走边打（不再遇到敌人就停下），可以缩小地图，也可以加一个“总攻”机制。
- **真机没测。** 只在 Chromium 模拟的视口里截图检查，触屏的长按和双指缩放是按事件逻辑写的。
- **骷髅骨堆期间不受控制效果影响。** 撒旦的深渊威压对正在重组的骷髅无效（review 的问题 4），记录在 `docs/QUESTIONS.md`，没有改。
- **受击白闪用缓存的亮化副本。** 旧版 Safari 上行为可能不同。
- **没有声音、没有存档、没有联网。**
