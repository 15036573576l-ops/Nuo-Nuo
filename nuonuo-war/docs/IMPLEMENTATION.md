# 糯糯战记 · 实现说明

单机网页兵线对战。玩家对电脑，不联网。纯原生 JS，没有框架，没有 npm 依赖。

## 构建和测试

```
python3 tools/build_game.py      # 生成 dist/game.html，双击即可打开
node tools/headless_test.js      # 无头测试：机制断言 + 定点技能场景 + AI 对 AI 50 局
```

`dist/gallery.html` 是之前的英雄图鉴，构建脚本没有变，仍然是 `tools/build_gallery.py`。

## 文件结构

```
src/rules.js            全局规则（已有，未改数值）
src/units.js            20 个兵种数据（已有，未改数值）
src/hd-sheets.js        精灵图帧信息（已有，由 tools/build_hd.py 生成）
src/sprite-render.js    精灵渲染（已有，本次只加了可选参数，见下）
src/game/combat.js      伤害管线、状态、元素反应、特性、主动技能。纯逻辑
src/game/engine.js      对局状态、固定步长主循环、经济、出兵、索敌、移动、攻击、胜负。纯逻辑
src/game/ai.js          电脑对手，三档难度。只通过 canSpawn / spawn 出兵
src/game/render.js      画面：背景、兵线、水晶、单位、血条、角标、投射物、特效、飘字、小地图
src/game/ui.js          界面：开局、出兵栏、HUD、输入、镜头、简介浮窗、结束统计、主循环
src/game.template.html  页面模板（样式和布局）
tools/build_game.py     把以上文件和精灵图内联成 dist/game.html
tools/headless_test.js  无头测试，只读源码
docs/QUESTIONS.md       规则里不清楚的地方，以及我采用的解释
```

逻辑和渲染分开：`combat.js`、`engine.js`、`ai.js` 不碰 DOM 和 canvas，`headless_test.js` 在 node 的 vm 里直接加载它们。

### 对已有文件的改动

`sprite-render.js` 只做了向后兼容的扩展，图鉴的调用方式不变：

- `drawHero(..., face, opt)` 多了一个可选参数 `opt`。
- `opt.once`：受击、死亡只播一次，停在最后一帧。
- `opt.period`：攻击动画按给定时长拉伸播完，出手帧 = `release` 帧的起点。
- `opt.flash`：受击白闪（`ctx.filter`）。
- `opt.alpha`：透明度，用于尸体淡出和地下蠕虫。
- 新增 `death` 状态。

## 主循环

`engine.update(realDt)` 把真实时间换成固定步长：每步 1/60 秒，每帧最多 12 步（防止卡顿时螺旋）。`speed` 为 1 或 2。`ui.js` 的 `requestAnimationFrame` 每帧调用 `update`，然后 `render.draw`。暂停时不调用 `update`，但仍然绘制。

一步 `step(dt)` 的顺序：

1. AI 的 `tick`（可能调用 `spawn`）
2. 经济：基础收入 × 难度系数 + 贪婪宝箱每个每秒 3 金币；出兵冷却递减
3. 每个单位：`tickStatuses`（持续伤害、状态计时、免疫计时、无敌、受击计时）；骨堆计时；技能冷却；盾墙计时；召唤物寿命
4. 每个单位：`updateUnit`（冲锋 → 蓄力 → 控制判定 → 技能 → 索敌和挥击 → 移动）
5. 投射物落地（回调里结算伤害）
6. 区域效果（火雨）、特效、尸体计时
7. 水晶炮塔
8. `settleDeaths`：本步内死亡的单位统一结算（骨堆、尸体、死亡特性）
9. `checkWin`

死亡是延后结算的。伤害函数只把 `hp ≤ 0` 的单位放进 `pending`，在步末统一处理。这样同一步里的其他单位不会因为别人的死亡改变行为。

## 单位状态

单位是普通对象，关键字段：

- `x`（兵线坐标）、`uy`（只用于画面错开的随机偏移）、`dir`（玩家 +1，电脑 -1）
- `hp` / `maxHp`
- `st`：状态表。`{ id: { stacks, t, absorb } }`，`t` 是剩余时间
- `imm`：`stun`、`frozen` 的免疫剩余时间
- `swing`：当前挥击周期（`t`、`period`、`releaseT`、`target`、`hit`）
- `cast`：蓄力中的技能（夜叉、奥林）
- `charge`：莱恩的冲锋剩余距离
- `skillCd`：技能冷却
- `bones`、`bonesT`、`reformUsed`：骷髅的白骨重组
- `burrowed`、`moving`、`hitT`、`clock`：给画面用的标记

### 状态系统

`Combat.applyStatus(eng, u, id, opts)` 是统一入口，叠层上限、持续时间、系数都从 `RULES.statuses` 读。特殊行为才单独写分支：

- 寒霜：叠满 3 层转为冻结；冻结后 4 秒内免疫再冻结；怕冷的蠕虫寒霜层数翻倍。
- 眩晕：巨型单位时间减半；眩晕后 2 秒内免疫；打断蓄力和攻击。
- 圣盾：吸收池，`absorb` 按量累加，时间刷新为 6 秒。
- 不屈：致命伤害时保留 1 点生命，无敌 1.5 秒，然后移除。
- 不死免疫中毒；雷克斯光环内的单位免疫衰弱。

`tickStatuses` 每步处理：持续伤害（燃烧 10/层/秒，中毒 6/层/秒无视护甲）、时间递减、过期删除、免疫和无敌计时。

### 伤害管线

`Combat.damage(eng, src, tgt, base, dmgType, opts)`，顺序：

1. 水晶：按重甲算，攻城 ×3。
2. 骨堆：只吃圣属性和溅射，直接散架。
3. 闪避（札斯 30% 闪避穿刺）和格挡（玄每第 4 次攻击完全格挡）。
4. 倍率：伤害类型 × 护甲（`RULES.damageMatrix`），然后是攻击方的衰弱、雷克斯光环、希尔薇对飞行 ×1.5、芙蕾雅对飞行或冲锋中 ×2、圣属性对不死 ×1.5、札斯的第一刀 ×2；被打方的史莱姆修正、易伤 ×1.2、盾墙（穿刺）×0.3。
5. 圣盾吸收。
6. 扣血，不屈判定，致死则登记死亡。
7. 元素反应（燃烧或冰冻目标被火打 → 融化；中毒 3 层以上被火打 → 爆燃）。

飘字颜色：倍率（护甲倍率或特殊倍率）> 1 时黄色，否则白色。

### 元素反应

- **融化**：火属性命中带寒霜或冻结的目标。移除寒霜/冻结，额外造成 `60 + 20 × 层数` 的魔法伤害（冻结算 3 层）。
- **爆燃**：火属性命中中毒 3 层以上的目标。移除中毒，以目标为中心 80 范围内的敌人受到 `15 × 层数` 伤害。
- **圣裁**：圣属性命中不死单位。伤害 ×1.5，骨堆直接散架。

反应伤害本身不再触发反应（`noReaction`），所以不会连锁。

## 索敌、移动、攻击

- **射程判定**：中心到中心的距离 ≤ `range + 12`。远程（`range ≥ 100`）可以打飞行单位，`groundOnly` 的除外。
- **索敌**：射程内最近的敌人。蝙蝠的规则不同：射程内有远程敌人就先打远程（不论距离远近）；射程内没有远程，就飞向全场最近的远程敌人。射程内没有单位就看水晶。碎城巨人只看水晶。
- **挡路**：地面单位被前方 22 像素内的敌方地面单位挡住。飞行、地下、碎城巨人既不挡也不被挡。同阵营不互相阻挡。
- **停下攻击**：射程内有目标就进入挥击，挥击期间不移动。
- **出手时机**：挥击周期 `1 / (aspd × 减速系数)`。伤害在 `release` 帧起点结算，不是攻击开始时。release 时目标已经不在射程内，就重新索敌；找不到就空挥。
- **投射物**：远程单位（以及箭塔）发射投射物。飞行时间 `距离 / 900`，限制在 0.12–0.7 秒。`homing` 的追着目标飞；炸弹落在发射时的位置，目标死了也会溅射。没有专用图的法术用元素颜色的光球。

## 主动技能

`SKILLS[uid]` 每个兵种一条，三种形式：

- `instant`：`when` 满足就立即生效（希尔薇、芙蕾雅、布朗、札斯、赛伦、莱恩、蠕虫、玄、摩尔德、雷克斯）。
- `channel`：蓄力 `dur` 秒后 `end` 生效（奥林 1 秒，夜叉 1.5 秒）。蓄力期间不能移动和攻击，眩晕和击退会打断，夜叉被打断后进入半冷却。
- 芙蕾雅的投矛是 `instant` 配合投射物；莱恩的冲锋是 `instant` 配合 `charge` 状态，每步前进 500 像素/秒，沿途每个敌人只吃一次伤害并被击退。

`trySkill` 在冷却好了且 `when` 返回计划时才释放，玩家和电脑的兵都一样。技能释放时在画面上飘出技能名。

## 电脑 AI

`AI.attach(eng, side, level)` 注册到引擎，每隔一段时间做一次决策。只调用 `eng.canSpawn` 和 `eng.spawn`，读取场上单位用来判断。

| 难度 | 收入 | 决策间隔 | 策略 |
|---|---|---|---|
| 简单 | ×0.8 | 1.6–3.0 秒 | 随机买一个买得起的兵，40% 的时候不买 |
| 普通 | ×1.0 | 0.5–0.9 秒 | 打分选兵，见下 |
| 困难 | ×1.15 | 0.35–0.6 秒 | 同普通，另外：场上贪婪宝箱少于 2 个、玩家兵少时优先买宝箱发育 |

普通和困难的打分（每个兵种一个分数，选最高的）：

- **克制**：我的 `strongVs` 匹配对方兵种 +1；对方的 `weakVs` 匹配我的兵种 +1；我的 `weakVs` 匹配对方 -0.8；对方的 `strongVs` 匹配我 -0.8。每种对方兵按数量计，最多算 3 个。匹配用包含关系（见 `ai.js` 的 `matches`）。
- **飞行**：对方有飞行单位时，能打飞行的远程 +0.5/个，近战 -0.5/个。
- **阵型**：远程太少时远程 +0.6，近战太少时近战 +0.6。
- **时间**：梯队在各自的峰值时间附近有加成（T3 约 25 秒，T0 约 270 秒），后期高梯队普遍加分。
- **花费**：前两分钟按花费扣分，之后只扣 1/5。
- **刷屏惩罚**：场上同一兵种越多越不想再买。
- **随机**：±0.15，避免完全确定。

除此之外有两条规则：

- **攒钱**：最高分的兵钱不够，但按当前收入 25 秒内能攒够，就先不买，不用便宜的兵凑数。
- **节奏**：开局 2 分钟后，如果场上没有 T0.5 或 T0 的兵，就只从这两档里挑（按分数，已经出过的少想一点），攒够钱就出。这是为了让大招能出场，否则高价兵几乎永远拿不到第一名。

## 画面和界面

- **镜头**：默认跟着前线（双方最前面的单位的中点）走，没有单位时停在己方一侧。手动拖动、方向键、滚轮、小地图点击会暂停自动跟随 3 秒。
- **背景**：Canvas 绘制。远山两层视差，草地，土路兵线，路上的刻度随镜头移动。
- **单位**：`SpriteRender.drawHero` 按状态选动画：受击（只播一次，白闪）、攻击（按挥击时钟拉伸）、跑步（移动或冲锋）、待机（其余）。钻地的蠕虫半透明并冒尘土。死亡的身体播完死亡动画后停在最后一帧，尸体在最后 1.5 秒淡出。
- **血条和角标**：血条按阵营颜色（我方蓝、敌方红），圣盾叠加在血条上方。状态角标用彩色方块加一个字（燃、寒、冻、毒、易、衰、盾、不、晕、定），层数大于 1 时显示层数。
- **水晶**：用 Canvas 画的水晶，发光脉动，受击闪白，带血条和炮塔冷却指示点。
- **飘字**：伤害数字（白或黄），反应名（融化、爆燃、圣裁、冻结、打断、闪避、化劲、不屈、骨堆等），技能名。飘字有竖向随机偏移，避免重叠。
- **界面**：HUD 显示双方水晶血条、金币（带每秒收入）、人口、时间、速度、暂停、小地图。出兵栏 20 个按钮，按梯队从 T3 到 T0 排列，每个按钮有头像（待机第一帧裁剪）、价格、人口、冷却遮罩；买不起时变灰。
- **简介浮窗**：鼠标悬停或触屏长按（420 毫秒）弹出，包含伤害类型、护甲、元素、射程、移速、生命、特性、技能（名称、冷却、描述、释放条件）、克制和怕的兵种、设定文字。
- **键盘**：`1`–`9`、`0` 和 `Q`–`P` 对应 20 个兵种按钮；空格暂停；`Z` 切换 1 倍速 / 2 倍速；方向键或 `A` / `D` 移动镜头。
- **结束**：水晶被打爆后等 1.6 秒（让最后的死亡动画播完），显示胜负、用时和双方出兵统计。“再来一局”用同一个难度。
- **横屏**：竖屏且宽度不超过 900 时显示“请横过来玩”的遮罩。

## 测试结果

用 `node tools/headless_test.js` 跑，在我的环境里的结果：

- 机制断言 20 项：全部通过。包括穿刺对重甲 ×0.6、寒霜叠满冻结和免疫期、融化和爆燃、骷髅的白骨重组（只一次）、近战打不到飞行、碎城巨人只找水晶、玄第 4 次格挡、雷克斯光环免疫衰弱、圣裁、出兵扣费和人口、冷却、武僧打断蓄力、芙蕾雅打断冲锋。
- 定点技能场景 12 项：每个主动技能各摆一个局面，断言技能放出来，效果对得上（穿云箭、钉刺定身、盾墙、影袭的 ×2、火雨、冲锋的圣盾、喷吐的灼烧、震山掌的击退眩晕、亡者复苏拉起骷髅、冰封冻结、居合伤害、王之号令的圣盾和不屈）。
- AI 对 AI 50 局（不渲染，9 种难度组合）：全部分出胜负，超时 0 局，NaN 0 次，平均时长约 218 秒（3.6 分钟）。
- 出兵次数（50 局合计）：除雷克斯外，20 个兵种都有出场。雷克斯的 AI 从不选，见下面的已知问题。

浏览器测试（Chromium 无头模式）：`dist/game.html` 双击式打开，控制台没有报错；做了开局、出兵、悬浮简介、2 倍速、结束面板、再来一局的流程；844×390 手机横屏视口截图检查过布局。

## 已知问题和没做完的部分

- **AI 对战偶尔拖很久。** 两边都在补灰鼠和骷髅时，前线可能长时间拉锯。早期试跑里有 1/50 局拖到 15 分钟，调整打分后这一轮没有超时，但没有从机制上根除。这是数值和 AI 强度的问题，不是死循环（已经单步追踪过，单位都在正常挥击、移动或重组）。
- **雷克斯 AI 不选。** 他的 `weakVs` 里有毒菇、霜语大法师和亡灵君主，场上这些兵一多，克制分就压低了，节奏规则里也常轮不到他。玩家手动出是可以的，他的技能用定点场景验证过。
- **没有真人试玩调平。** “简单能赢、困难需要动脑”只是按数值推的，没有实测。平均时长和胜负比例只来自 AI 对 AI。
- **手机没有实机测试。** 只在 Chromium 的 844×390 视口里截图检查。触屏的长按、滑动镜头是按事件逻辑写的，没有在真机上确认手感。
- **小地图很小。** 高 16 像素，只能看大致位置。
- **个别特效是简化版。** 火雨、冰封、居合、冲锋都用线、锥、环来表现，没有专门画的特效图。
- **受击白闪依赖 `ctx.filter`。** 旧版 Safari 不支持，那里没有白闪，其余正常。
- **同一步内的顺序有轻微影响。** 比如蝙蝠和近战同时挥击时，先后会影响谁先结算。测试里这个影响没有看出偏差。
- **没有声音、没有存档、没有联网。** 按要求不做联网。
- 灰鼠群“被溅射打到会成片倒下”没有实现额外效果，见 `docs/QUESTIONS.md` 第 18 条。
