# 任务：实现网页单机对战游戏《糯糯战记》

你要在仓库 `15036573576l-ops/Nuo-Nuo` 的 `claude/nuonuo-war` 分支上，在 `nuonuo-war/` 目录里实现一个完整可玩的网页游戏。玩法参考横版兵线对战（类似《米拉奇战记》《Stick War》）：两边各有一个水晶，花金币出兵，兵自己往前走、自己打，先打爆对方水晶的一方赢。**单机，玩家对电脑 AI，不做联网。**

## 一、已经有的东西（先读这些，不要重写）

| 文件 | 内容 |
|---|---|

| `src/rules.js` | **全局规则**（`window.RULES`）：兵线长度、水晶血量和炮塔、经济、伤害类型×护甲倍率表、远程判定阈值、所有状态（灼烧/寒霜/冻结/中毒/易伤/衰弱/圣盾/不屈/眩晕/定身）的叠层和持续时间、三个元素反应（融化/爆燃/圣裁）。 |
| `src/hd-sheets.js` | 由 `tools/build_hd.py` 生成。每个兵种精灵图的帧宽、帧高、脚底锚点、身体宽高、各动作（idle/run/attack/hit/death）的帧数、帧率、出手帧；`_projectiles` 里是箭、长矛、炸弹、孢子、火球的投射物条带。 |

`units.js` 里每个兵种的 `sheet` 字段就是它在 `HD_SHEETS` 里的 key，`projectile` 字段是 `_projectiles` 里的 key。

## 二、要做的东西

### 1. 文件结构

新建这些文件（纯原生 JS，不用框架，不用打包工具）：

```
src/game/engine.js     游戏状态、主循环（固定步长 1/60 秒逻辑 + requestAnimationFrame 渲染）
src/game/combat.js     伤害计算、状态系统、元素反应、技能
src/game/ai.js         电脑对手
src/game/render.js     画战场、单位、血条、投射物、特效、飘字
src/game/ui.js         出兵栏、金币、人口、水晶血量、开始/结束界面
src/game.template.html 页面模板
tools/build_game.py    内联成 dist/game.html（单文件，双击就能打开）
```

逻辑和渲染必须分开：`engine.js` / `combat.js` / `ai.js` 不能碰 canvas 和 DOM，这样以后能在 node 里跑测试。

### 2. 战场

- 一条横向兵线，长度 `RULES.lane.length`（1600）。左边玩家水晶，右边电脑水晶。画面宽度不够时镜头可以左右拖动（鼠标拖拽、触屏滑动、键盘方向键），并且有一个小地图条显示双方兵力位置。
- 单位只有 x 坐标（加一点随机 y 偏移只用于画面错开，不影响逻辑）。
- 水晶：血量 `RULES.lane.crystalHp`，自带炮塔（`RULES.crystal`），能打飞行单位。
- 背景用 canvas 自己画（天空渐变 + 远景剪影 + 地面），不要引入外部图片。

### 3. 规则（严格按 rules.js 和 units.js 实现）

- **经济**：开局 `startGold`，每秒 `income`；人口上限 `supplyCap`。出兵要同时满足：金币够、人口够、该兵种冷却好了、`maxOnField` 没到上限。
- **出兵**：从己方水晶前出现，`count` > 1 时一次出多个（人口只算一次）。
- **移动与索敌**：单位向前走，射程内有能打的敌人就停下攻击，攻击最近的敌人。近战（`range < rangedThreshold`）打不到飞行单位；`groundOnly` 的远程也打不到。同阵营地面单位不互相阻挡，敌方地面单位会阻挡地面单位（飞行单位不被阻挡）。
- **特殊索敌**：飞行单位优先打远程单位；碎城巨人无视所有单位直走水晶；贪婪宝箱 `speed: 0` 驻守在自家水晶前。
- **伤害**：`最终伤害 = 攻击 × damageMatrix[伤害类型][护甲] × 各种修正`。修正包括：易伤 ×1.2、衰弱 ×0.7、征服王光环 ×1.15、圣属性打不死单位 ×1.5、希尔薇打飞行 ×1.5、芙蕾雅打飞行/冲锋中目标 ×2、史莱姆受穿刺 ×0.6、史莱姆受火 ×1.5。攻城伤害打水晶 ×3。圣盾先吸收伤害。
- **状态**：完全按 `RULES.statuses` 的叠层上限、持续时间、刷新方式实现。寒霜叠满 3 层变冻结，冻结后有免疫期；眩晕后有免疫期；巨型单位免疫击退、眩晕减半；不死单位免疫中毒。状态系统写成数据驱动：一个通用的 `applyStatus(unit, id, stacks)` 和每帧的 `tickStatuses`，不要每个状态写一套。
- **元素反应**：按 `RULES.reactions`，火打寒霜/冻结 → 融化；火打 3 层以上中毒 → 爆燃；圣打不死/骨堆 → 圣裁。
- **被动特性和技能**：每个兵种的 `traits` 和 `skill.desc` 写得很具体，照着实现，数值以 desc 里写的为准。技能全部**自动释放**：冷却好了且满足 `skill.when` 就放，玩家和电脑一样。开局技能冷却从 40% 开始。有蓄力的技能（奥林冰封 1 秒、夜叉居合 1.5 秒）蓄力时头上显示进度条，被眩晕/击退打断。
- **尸体**：单位死亡后尸体保留 `corpseSeconds` 秒（播放 death 动画后留最后一帧并逐渐变淡），摩尔德的技能从尸体拉骷髅。召唤物不占人口、不留尸体。
- **胜负**：一方水晶血量归零即结束，显示胜利/失败、用时、双方出兵统计，按钮“再来一局”。

### 4. 电脑 AI（`ai.js`）

三档难度：简单 / 普通 / 困难，开局界面选择。

- 简单：每隔几秒随机出一个买得起的兵，收入 ×0.8。
- 普通：维护“前排 / 远程 / 应对”比例；看玩家场上兵种的 `weakVs`/`strongVs`，有一定概率出克制它们的兵；钱多时攒一波一起出；会在劣势时补贪婪宝箱以外的兵防守。
- 困难：在普通基础上收入 ×1.15，更积极地针对克制，会在玩家兵少时买贪婪宝箱发育，会留钱应对碎城巨人。
- AI 只能通过和玩家一样的“出兵”接口操作，不允许直接改游戏状态。

### 5. 界面（`ui.js`）

- 底部出兵栏：20 个兵种按梯队排列，每个按钮显示头像（用 idle 第一帧裁剪）、价格、人口、冷却遮罩；钱或人口不够时变灰。电脑上数字键 1–0 和 Q–P 对应前 20 个按钮。手机上出兵栏可以横向滑动。
- 顶部：金币（带每秒收入）、人口、双方水晶血条、暂停按钮、1×/2× 速度切换。
- 长按（手机）或悬停（电脑）兵种按钮，弹出简介：伤害类型、护甲、元素、特性、技能、克制谁、怕谁（来自 units.js）。
- 单位头顶：血条（敌我颜色不同）、状态小图标（灼烧/寒霜/中毒/诅咒/祝福，用简单的彩色小方块+字即可）、技能释放时飘一行技能名。
- 伤害飘字：普通白色，克制倍率 > 1 时黄色，元素反应时用反应名显示。
- 手机横屏可玩：canvas 自适应窗口，竖屏时提示旋转。

### 6. 表现

- 用 `SpriteRender` 画单位，敌方 `face = -1`。按单位自己的状态切换 idle / run / attack / hit / death 动画，攻击在 `release` 帧真正结算伤害或发射投射物（不要在攻击开始就扣血）。
- 投射物用 `_projectiles` 的条带图，没有专用图的法术用彩色光球（元素颜色：火橙、冰蓝、毒绿、暗紫、圣金）。
- 技能特效用 canvas 画就行：火雨的落点圆、冰封的蓝色圆、居合的直线刀光、冲锋的拖影、圣盾的金色描边。
- 像素图放大一律 `imageSmoothingEnabled = false`。

## 三、验收标准（做完自己逐条检查）

1. `python3 tools/build_game.py` 生成 `dist/game.html`，**直接双击打开就能玩**，控制台没有报错。
2. 20 个兵种都能出、都能打、都有正确的动画；有技能的 15 个兵种能看到技能触发。
3. 每条克制关系至少能观察到效果：弓箭打飞行、飞行越过近战、溅射清鼠群、史莱姆分裂、骷髅重组、巨人直冲水晶、冰冻后被火打出“融化”、芙蕾雅打断冲锋、武僧打断蓄力。
4. 一局正常对战 3–8 分钟能结束，简单难度新手能赢，困难难度需要动脑。
5. 新增一个 `tools/headless_test.js`：在 node 里用 engine/combat/ai 跑 AI 对 AI 50 局（不渲染），输出平均时长、各兵种出场次数和胜率，确认没有死循环、没有 NaN、每局都能分出胜负。
6. 手机横屏能完整操作。
